# Dépôt

* [Repository](repository.md) - Dépôt GitHub et services rattachés, gérés par l'agent via leurs API ; documentation du dépôt (README.md, README.dev.md).
* [Signature des commits](signature-des-commits.md) - Commits signés et vérifiés, vérification sur GitHub seulement ; s'applique à tout commit.
* [Configuration du repository GitHub](configuration-du-repository-github.md) - Réglages du dépôt GitHub, branche main et ancienne branche master archivée, Ruleset de main, sécurité du dépôt, merge fait par l'agent au nom de l'utilisateur, jamais par un collaborateur ; à lire pour toute modification de la configuration GitHub.
* [Intégration continue (CI)](integration-continue-ci.md) - Workflows CI, tests selon ce que modifie la Pull Request, aucun check sur une Pull Request en conflit avec sa branche de destination, checks requis tenus alignés sur le Ruleset, secrets, quota de l'API GitHub consommé par chaque push.
* [Analyse de la qualité du code](analyse-de-la-qualite-du-code.md) - Analyse SonarQube Cloud : workflow, porte de qualité (bloquante dès que l'état du code le permet, au plus tard à la fin de la Phase 2), jetons, périmètre et exclusions, nouveau code ; à lire pour modifier l'analyse ou sa configuration.
* [Mises à jour des dépendances](mises-a-jour-des-dependances.md) - Versions épinglées, relevé des versions, vulnérabilités connues, montées et leur revue de l'existant ; à lire quand le relevé est dû ou pour toute montée de version.
* [Contrôle qualité hebdomadaire](controle-qualite-hebdomadaire.md) - Contrôle hebdomadaire du code global de main (SonarQube Cloud, règles de style, tests de mutation), rien de bloquant, ticket de suivi de la dette qualité par urgence (critique, prioritaire, au fil de l'eau), traitement borné à une Pull Request par semaine ; à lire quand le traitement est dû ou pour modifier le contrôle.
* [Traitement du contrôle qualité à la reprise du travail](traitement-du-controle-qualite-a-la-reprise-du-travail.md) - À chaque reprise du travail, avec le relevé des versions : quand le traitement des entrées du contrôle qualité est dû et où sa trace se lit ; s'il est dû, lire Contrôle qualité hebdomadaire.
* [Relevé des versions à la reprise du travail](releve-des-versions-a-la-reprise-du-travail.md) - À chaque reprise du travail : quand le relevé des versions est dû et où sa trace se lit ; s'il est dû, lire Mises à jour des dépendances.
* [Règle absolue : interdiction de pousser directement sur `main`](regle-absolue-interdiction-de-pousser-directement-sur-main.md) - Interdiction de commiter ou pousser sur main : toute modification passe par une Pull Request.
* [Stratégie de branches](strategie-de-branches.md) - Branches persistantes (main, branches de release et archive/master seules), nommage des branches (feat/, fix/, chore/), branche de travail tenue à jour de sa branche de destination.
* [Conventions de commit](conventions-de-commit.md) - Conventional Commits pour les commits et titres de PR, description de PR devenue corps du commit squashé, template de PR.
* [Versions et releases](versions-et-releases.md) - Numérotation semver à partir de la version 10, jalons, rattachement des tickets et PR, publication d'une version (tag, release, installeur, analyse).
* [Reprise depuis l'amont](reprise-depuis-l-amont.md) - Reprise ponctuelle d'une fonctionnalité du dépôt d'origine (TV-Rename/tvrename) par un chantier : décision, analyse de l'ajout dans l'amont, intégration en tenant compte des personnalisations du fork, trace ; veille mensuelle de l'amont (harnais upstream-watch) ; à lire pour tout chantier de reprise ou quand l'analyse de la veille est due.
* [Veille de l'amont à la reprise du travail](veille-de-l-amont-a-la-reprise-du-travail.md) - À chaque reprise du travail, après le traitement du contrôle qualité : quand l'analyse de la veille de l'amont est due et où sa trace se lit ; si elle l'est, lire Reprise depuis l'amont.
